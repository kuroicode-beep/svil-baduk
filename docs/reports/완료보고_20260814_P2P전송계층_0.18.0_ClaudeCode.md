## 핵심 발견 — 공개 PeerJS 클라우드의 payload 스키마 검증

원인 불명의 "중계 실패"를 계층 분해로 추적했다:

1. 순수 Dart 소켓 → 등록(OPEN)은 되는데 OFFER 를 보내면 **서버가 소켓을 close 1000/1011 로 조용히 닫음**
2. 같은 ID 이중 등록 → ID-TAKEN = 같은 realm (인스턴스 분리 아님)
3. **실브라우저 + 공식 peerjs 클라이언트**(WebSocket 몽키패치로 프레임 관찰) → 정상 동작, 공식 프레임 형태 확보
4. 공식 필드 집합(`sdp`·`type:'data'`·`connectionId`·`label`·`reliable`·`serialization`)을 그대로 보내자 **즉시 중계 성공**

→ 신형 클라우드는 시그널 payload 를 스키마 검증하고, 안 맞으면 오류 없이 연결을 끊는다. 앱은 공식 형태를 보내도록 구현했고, `test_live/` 가 이 형태로 실서버를 상시 검증한다.

## 프로토콜 결정

- 어긋남 복구는 **호스트 판이 권위** — 게스트는 StateRequest, 호스트는 자기 StateMsg 를 직접 보낸다 (양쪽 StateRequest 는 교착)
- React(BinaryPack) 판과 교차 대국 없음 — 로비에 명시
- 방 ID `svb-` + 6자 (0/O·1/I/l 제외) — 한 글자씩 낭독 가능
